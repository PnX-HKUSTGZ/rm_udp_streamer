# 接收、设备选择与渲染切换

普通启动进入交互界面，恢复上次保存的监听地址、来源过滤、解码器、设备、传输和节奏。传入任意接收器命令行参数时从文档默认值开始，便于部署和验证复跑；不会从交互设置继承隐藏的来源过滤。定时退出、自动开始和输出文件名不保存。

## 连接与过滤

监听地址填写本机数字 IPv4 地址，`0.0.0.0` 监听所有 IPv4 接口，默认 UDP 端口为 `3334`。限定来源 IP 留空表示任意地址，来源端口 `0` 表示任意端口。填写后，两项同时匹配的数据包才进入重组；界面底部继续显示实际锁定的发送端地址和端口。

命令行示例（放在 Godot 的 `--` 后）：

```text
--start --bind 0.0.0.0 --port 3334 --source-ip 192.168.1.20 --source-port 5000 --decoder auto --transfer yuv
```

端口过滤需要发送端保持相同来源端口。它是接收筛选，不是发送方身份认证或网络加密。

## 设备与实际路径

列表按当前包编入的后端及实际可访问设备生成。未编入或未枚举到可访问设备的硬件解码选项不可选，提示中保留原因；安装驱动、修复权限或改变设备后点击“刷新设备”。列表证明可枚举，不承诺某个 HEVC profile、像素回读或 GPU 互操作已通过。

选择具体设备时使用其完整 UUID、LUID 或 PCI 标识。默认设备使用后端局部序号 `0`。高级输入允许显式序号/标识，实际初始化仍核验设备身份，错误会明确报告。Windows LUID 仅在当前系统启动期间有效；重启系统后可能需要重新选择。完整规则见[设备身份](devices.md)。

- `CPU YUV`：硬解帧先回读，再上传原生平面；软件解码直接准备平面。
- `CPU RGBA`：在准备线程转为 RGBA，便于兼容不同显示路径。
- `GPU CUDA / OpenGL`：要求明确选择 CUDA 和 OpenGL 兼容渲染。界面禁用已知不成立的组合；实际收到帧后继续核验设备匹配、NV12 8 位格式和同步能力。不满足时明确失败。
- `自动 GPU / CPU`：允许尝试 GPU 桥接；不可用时继续 CPU YUV，保留实际路径和回退原因。选定带后端的设备身份后，自动解码只尝试该后端再回退软件。

## 切换渲染器

选择 Vulkan Mobile 或 OpenGL 兼容，然后点击“重启并切换”。应用保存连接和设备设置，停止接收并等待资源退役后重启；保留当前屏幕选择，以及 Linux 的 Wayland/X11 显示方式。重新打开后手动开始接收。停止超过 5 秒时不自动重启，并显示错误。定时验证运行不提供该操作。

渲染器选择不改变正在运行的进程。当前渲染设备、实际解码设备、传输路径、信号过期和回退原因均显示在状态区域；仅选中一个菜单项不能作为实际路径生效的证据。

“低延迟”节奏增加处理频率和功耗，OpenGL 下关闭显示同步，可能撕裂。处理上限不是视频帧率；性能结论以完整秒窗口的新纹理提交计数为准。普通界面和定时退出使用单调实时时钟。

## 设置存储与验证状态

设置保存到 Godot 的 `user://receiver.cfg`，经同目录临时文件替换；不写入工程资源。读取失败时保留原文件、使用默认值并显示提示。命令行使用 `--help` 查看全部参数。

R5 当前已完成 Windows 与原生 Ubuntu 的界面能力、设置往返和实际 UDP 来源过滤集成检查。Windows 已验证 1100×720 窗口布局和 Vulkan Mobile 到 OpenGL 的实际进程重启，连接、设备和播放设置保留且不自动接收；新增的屏幕保持参数待 Windows 回归。Ubuntu AMD 已验证相同重启流程及 Wayland 显示方式保持，C# 构建零警告。两平台已有中间候选的独立导出、无 SDK 启动和重链接后硬解播放证据，后续改动仍需对应最终包复核；R5 尚未通过阶段审查。

AMD Ubuntu 当前有完整长测证据的组合为 Wayland、Vulkan Mobile、VAAPI/CPU YUV、低延迟节奏。例如启动包时可指定 `--display-driver wayland --rendering-method mobile -- --decoder vaapi --cadence responsive`。默认桌面方式/节奏的一轮工程检查曾降至约 10 fps，不能将已测组合的性能结论套用到默认配置或 X11。
