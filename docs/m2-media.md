# M2：HEVC 解码与 CPU 呈现

实现提交 `be62ebd`，2026-11-15。**M2 已通过 gpt-6-astra 独立审查**，两个颜色契约问题修正后完成独立回归，见 [审查记录](evidence/m2/review.md)。M3 恢复/独立导出和 M4 GPU bridge 尚未完成。

## 实现范围

- 原生 FFmpeg HEVC parser 保持跨传输组状态，支持一个组零/多个输出，不依赖 AUD。压缩输入有 FFmpeg 零填充，解析器累积有 8 MiB 上限，默认解码像素上限 1920×1088（包括 HEVC 编码补齐区域）。
- `FrameLease` 持有 AVFrame 强引用，记录流/资源代际、编码尺寸/裁剪/可见尺寸、像素格式/位深、颜色元数据、像素比例、实际解码后端/设备和本地输出序号。协议无 PTS，未伪造一组等于一帧或端到端延迟。
- 解码线程完成软件/硬件解码、硬件像素回读、原生平面打包或 SDR RGBA 转换；最新帧邮箱仅保留一张待显示图像。Godot 渲染线程执行原生上传，最多一个上传任务在途；回调强引用保留数据，停止/移除显示节点不能提前释放待执行的数据。
- NV12、YUV420P/YUVJ420P 原生上传平面，shader 匹配 BT.709/BT.601/BT.2020 NCL 的范围和矩阵，并处理色度位置。通用 RGBA 使用固定 FFmpeg swscale。视频像素不经过 C# 数组或 Variant 像素通道。
- Main10 默认明确拒绝；显式允许 `allow_10bit_to_8bit` 时转换为 RGBA8 并报告精度降低。PQ/HLG 明确拒绝，首版不进行 HDR 色调映射。显示色域仅支持已标注 BT.709 或未标注时采用 BT.709 默认值；BT.2020/P3 等其他已标注原色明确拒绝，因为矩阵转换不等于显示色域转换。未知 range/matrix/chroma 按已记录的 SDR 默认解释并显示提示，未指定 transfer 保持为未知且按 SDR 解释。其他不支持矩阵拒绝。
- 界面显示实际后端/设备/传输、来源、尺寸、重组/解码/新画面提交速率、丢弃/回读和错误；新画面提交不是屏幕实际显示 FPS。停止请求异步，后台完成后才能重启。

传递函数接受 BT.709、SMPTE170M、sRGB、BT.2020 10/12 bit 的传统非线性 SDR 曲线或未指定（默认 SDR 解释）；未实现传递函数转换，因此 LINEAR、LOG 等其他已标注曲线明确拒绝。BT.2020 原色即使使用 SDR 曲线仍按上述色域门槛拒绝。

## 已执行验证

Windows 40 个解码案例、WSL 20 个案例全部通过：软件、CUDA，以及 Windows Intel/NVIDIA D3D11VA。每个成功案例输出 120 帧；8 位输出按统一 Y/U/V 排列逐帧摘要完全匹配软件参考。包含 1080p60、BT.709、全范围 BT.601、无 AUD 且含 B 帧、Main10 显式转换/默认拒绝、非方形像素比例、HDR/宽色域 SDR/LINEAR 拒绝。测试故意以不同长度拆分传输组，跨越 NAL/图像边界。

两平台独立平面检查覆盖负 stride、可见裁剪、奇数尺寸、NV12 双通道布局与无边界输入的解析器预算。两平台图形矩阵共 14 张色条/灰阶/比例截图与 FFmpeg 软件参考比较，采样最大通道误差为 3/255；RGBA 为 0，包含 Mobile/Vulkan 与 Compatibility/OpenGL。

两平台完整 C# 界面通过真实 `stream_sender/sender.py` 文件循环输入（640×360、60 fps、360 帧），实际视频可见，停止后端口可重新绑定。WSL 为 llvmpipe/WSLg 显示与 CUDA 解码，不能代替原生 Ubuntu GPU 互通验收。

## 性能口径与限制

固定 M0 1080p60 样本通过真实 UDP 连续发送 360 组，实际输入约 60.16 fps。软件 Windows 得到 359 个解码帧/350 次提交；CUDA Windows 359/280；WSL 软件 359/358、CUDA 359/356。持续流 parser 为判定访问单元边界保留最后一个未确认帧，所以无 EOS 的有限网络运行比离线 `finish()` 少一帧。

稳定观测区间中，解码约 60 fps；Windows CUDA 的 CPU 中转提交约 42–47 fps，其他上述短测多为 57–61 fps。**这些是功能短测，未完成稳定性、固定资源负载、发布包与最终性能验收，也不宣称所有组合已达 1080p60。** 首次硬件设备初始化可能赶不上流首个 IDR，因此本轮 WSL 的一个 360 组颜色案例和完整 UI 案例仅解码 299 帧，其余在下一 IDR 恢复；后续必须在 M3 单列启动/恢复等待。

网络头无媒体时间戳，parser 可能跨组；本实现暂不报告无法关联的首包到纹理提交 P95/P99，也不把解码线程耗时当作摄像头到屏幕延迟。M3/M6 在已证明输入输出关联的条件下补充测量；无法关联时保留未知。
