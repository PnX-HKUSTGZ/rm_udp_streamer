## 输入与回退

基线为 1920×1080、60 fps、HEVC 8 位 4:2:0 SDR。矩阵/range、裁剪、比例、色度位置和格式变化按实际输入元数据处理。Main10 的 CPU 路径需显式允许降精度；HDR、未支持的宽色域及 LINEAR/LOG transfer 明确拒绝。GPU 桥接当前限定 NV12 8 位、CUDA 与 OpenGL 同设备，仍包含 GPU 内复制。

`--transfer gpu` 要求明确选择 CUDA，不满足条件时失败。`--transfer auto` 允许 GPU 尝试失败后保留解码并回退 CPU YUV，界面报告实际路径和原因。VAAPI 仅交付 CPU 回读路径；VAAPI/DMA-BUF/Vulkan、D3D11/Vulkan 直传尚未实现。

Intel接屏后的完整10/60工程对照中，balanced为55.8667/55.85fps，performance为57.5667/57.05fps，均未达到门槛。临时UI刷新探针有改善，但不是发行候选的正式性能证据。实际画面、生命周期、失败记录、恢复状态及完整归档见[Intel补验报告](evidence/r4/report.md)。

固定样本与模拟发送器能验证协议处理及恢复逻辑。真实UDP曾接入本机`192.168.12.2:3334`：先前中途捕获有IDR而没有VPS/SPS/PPS，解码失败；随后提前监听并重新开流，网卡抓到第1组参数集与IDR，同一发行包已实际D3D11VA硬解1920×1080并显示真实画面，独立FFmpeg也成功。历史观察见[真实流检查](evidence/r4/real-stream.md)。bac87ac 的显式启动参数、直接接收和进程重启记录见[断流与重连验收](evidence/r4/disconnect-recovery.md)，其中 Ubuntu 首轮进程退出失败保留为历史问题。后续 1366817 包的停止修复和两台 Ubuntu 各 60 次独立进程退出已通过，见[当前候选记录](evidence/r6/candidate-1366817.md)。当前自动缓存可复用匹配来源的已验证参数；没有带内参数或匹配缓存时仍等待参数。用户关闭真实推流后的新候选使用回放验证，完整平台、性能和阶段验收仍未完成，不声明新的实流验收或相机到屏幕延迟。

## 运行与依赖

解压后运行 `RmVideoReceiver.exe`（Windows）或 `RmVideoReceiver.x86_64`（Ubuntu）；保留包内文件结构。包应自带 Godot 与 .NET 运行时，仍需操作系统的显示环境和 GPU 驱动。Ubuntu 基线为 24.04 x86_64、glibc 2.39、X11/Wayland，以及标准 .NET 原生依赖和 fontconfig；不声明兼容 Ubuntu 22.04。

旧官方 Linux FFmpeg 锁没有 VAAPI。启用 VAAPI 的候选使用独立 developer 锁，包中记录实际依赖类别及摘要。VAAPI 包启动时需系统 `libva2`、`libva-drm2`、`libdrm2` 和对应 Intel/AMD 媒体驱动，即使选择软件解码也不能省略这些动态依赖。

88bf17a候选已在Windows和原生Ubuntu干净检出完成导出、许可/源码材料清单、实际重链接及无SDK启动，新包分别完整核验512/476成员；原始与重链接包均实际硬解播放。准备/提交独立显示和双平台实际UI已经R5独立复审通过，见[构建阶段报告](evidence/r5/report.md)。性能、生命周期和故障仍逐项对应包内manifest的提交与摘要；故障注入副本与未修改发行库分列。`validated: false`的开发者依赖不因部分测试通过而自动升级为通用已验收依赖。
