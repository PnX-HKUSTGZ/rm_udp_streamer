# 参数来源与启动验证

2026-11-16。普通启动必须从实机输入自动取得解码参数，禁止向工程加入此前捕获的固定参数。当前实机中途接入尚未验收通过，本项不关闭 R4/R6。

## 先前参数的来源

VPS/SPS/PPS 是 HEVC 标准的参数集，实际值来自真实启动抓包 `restart-wire-v2/stream.pcapng`，SHA256 `9ed6ef8073cd40f0f9be85b0c82219245be0c122f53324da39c1bf5f7141b151`。第 42 个包来自 `192.168.12.1:57108`，`frame_id=1`、分片 0；UDP 负载偏移 8/35/91 分别是 VPS/SPS/PPS，共 94 字节，随后是 IDR。它们不是根据分辨率猜出的配置。后来通过 `--hevc-parameters` 手动加载的就是这份数据；那些结果只证明具备参数时能够解码，不证明普通工程能够冷启动接入。

## 最新实机无参数文件观察

工作区基线 `5fbcc061a15a68bd5dfa0b652d3b0aa33c5f4003`，未设置 `--hevc-parameters`。网卡独立抓取 55 秒，收到 `192.168.12.1:49940 → 192.168.12.2:3334` 的 41,109 个视频 UDP 包、重组 3,298 个完整组、55 个 IDR，VPS/SPS/PPS 为零。原始 UDP 负载扫描与独立重组扫描一致，捕获丢包为零；同时运行的应用重组 2,700 组，解码和提交均为零。完整抓包 SHA256 `c3039f28af617dbe327cbf0541e88a34d1c2113911bc26cbff4399e0419851d5`。

官方自定义终端文档仅规定监听 UDP 3334、HEVC、无重传机制；已核查的参考客户端也从码流解析参数，没有可据以实现的参数重取命令。此结论限于当前资料及观测窗口，不能推断设备永久不重发。

## 接收器初始化时丢参的独立缺陷

原实现先监听 UDP，再在消费线程中初始化 GPU。压缩队列的年龄预算为 50 ms，硬件打开期间可能将唯一参数组丢弃。使用完整录制启动组作为正常 UDP 输入，仅第一组含参数，接收器不加载参数文件；600 组、60 fps 的相同输入得到以下结果：

| 路径和启动时机 | 解码帧 | 队列过期组 | 主线程接受 |
| --- | ---: | ---: | ---: |
| 原 CUDA，绑定后立即输入 | 0 | 8 | 0 |
| 原 CUDA，绑定后延迟 1 秒输入 | 540 | 2 | 539 |
| 修复后 CUDA，绑定后立即输入 | 540 | 7 | 539 |
| 修复后 D3D11VA，绑定后立即输入 | 540 | 3 | 539 |
| 正式构建入口重建后 CUDA，绑定后立即输入 | 540 | 6 | 539 |

修复先建立轻量解析器，取得本次输入的参数及随机访问帧后再打开后端；首帧解码成功后，后续积压丢弃继续使用正常的已验证参数缓存恢复。没有预置配置，没有增加队列容量或年龄上限。表格是本地 UDP 录制回放的功能验证，不能替代当前实机的普通工程启动验收。

Windows 软件/D3D11VA/CUDA、Ubuntu 24.04 AMD 软件/VAAPI 均通过延迟打开与立即打开的逐像素比较、缺参数等待、空流结束、失败设备一次性回退、同源断流缓存、换源隔离及原恢复/传输回归。产品原生源码 SHA256 与测试记录绑定。原始脚本、构建和结果位于外层 `processing/2026-11-16-rm-editor-live-start`；启动测试工具首版失败也保留。尚未完成本次变更后的正式性能、完整发行包复验和阶段独立审查。

重建的 Ubuntu 扩展还通过真实 Godot 无窗口加载及异步 VAAPI 接收会话：从正常 UDP 输入自动取得唯一的启动参数，解码 599 帧、硬件帧 599、解码错误 0，正常退出并成功重绑端口。工具 v1 因漏设本机 Mono 引擎需要的 `DOTNET_ROOT` 未能启动，原记录保留；v2 补齐环境后通过。这项不验证屏幕显示。
