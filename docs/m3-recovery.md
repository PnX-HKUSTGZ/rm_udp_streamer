# M3：恢复与 D1 独立兼容包

2026-11-15。实现提交 `6ce1a13`（恢复）、`2b722b4`（最终 D1 构建/部署入口）。本报告是 M3 送审依据；独立审查通过前不进入 M4。

## 恢复与资源契约

- 有界 HEVC RBSP 读取按 slice PPS → SPS → VPS ID 选择参数：16/16/64 个槽，单参数 64 KiB、总缓存 256 KiB、每访问单元最多 1024 个 NAL。丢包可复用同会话参数，换来源/会话代际清空。输入错误回退到曾成功产生画面的参数，避免损坏更新污染恢复。
- 不连续和可恢复的输入错误进入 Recovering，清除接受代际并等待 IDR/BLA/CRA。恢复 CRA/BLA 时丢弃 RASL，遇到正常后续图像后结束此限制。不可支持的颜色/格式、设备错误保持明确失败；实际格式导致的自动硬件回退属于 M5。
- 资源代际覆盖编码/可见尺寸、裁剪、SAR、位深、像素格式、颜色和解码设备。上传前、发布前、主线程接收时均检查代际。停止、故障和不连续立即使旧代际失效；超过 2 秒的帧不能再发布/显示。
- 界面在画面年龄超过 500 ms 时提示过期，2 秒后清屏。有效画面年龄独立于无效包流量。CPU 上传强引用继续保证在途源数据的生命周期；像素仍不经过 C#。

## 验证与边界

六组原生检查：Windows 软件、CUDA、两个 D3D11VA 设备；WSL 软件、CUDA。每组均通过同会话缺帧且 IDR 不重复参数（89 帧逐帧一致）、新代际拒绝旧参数、错误恢复、CRA 中途加入（90 帧，丢弃 1 个 RASL），以及 range → Main10 → 分辨率变化（480 帧与代际递增）。

四组真实 Godot 图形链（两平台软件/CUDA）依次经历正常、缺帧、损坏 HEVC、2.5 秒断流、换发送端与分辨率、全范围、Main10、1800 组过载和恢复 720p。各组 15–21 次恢复、1 次明确解码错误；最后均恢复 1280×720、2 秒清图通过。每组另执行 12 次带实际视频的启停，交替 YUV/RGBA，检查新代际及端口重绑，errors 均为空，Godot 日志无 ERROR/SCRIPT ERROR。

压缩流没有 PTS，parser 允许跨组；没有伪造首包至提交 P95/P99。恢复等待分为设备准备、上游随机访问点及本地处理，本阶段仅验证有可用随机访问点时能够恢复，不声称任意发送器都能在固定毫秒内恢复。强制设备错误不会被错误标为成功；完整自动降级矩阵在 M5 验证。

## 固定输入短测

固定 M0 `probe1080.hevc`，HEVC Main、8 bit、1920×1080、60 fps，以真实 UDP 发送 600 组；Godot 4.7.2、FFmpeg n8.1.3、Mobile/Vulkan、960×540 窗口。发送实测 60.095–60.098 组/秒。Windows 为 RTX 5070 Laptop、驱动 591.74；WSL Ubuntu 24.04 为 WSLg/llvmpipe，CUDA 在同一 NVIDIA 上解码。未隔离系统其他负载，属于可重复条件的短测，不是长期性能保证。

| 环境/解码 | 解码帧 | 新纹理提交 | 稳定区间平均提交 fps | 最低一秒提交 fps |
| --- | ---: | ---: | ---: | ---: |
| Windows 软件/CPU YUV | 599 | 582 | 58.70 | 56.97 |
| Windows CUDA/CPU NV12 | 599 | 540 | 52.99 | 43.91 |
| WSL 软件/CPU YUV | 599 | 599 | 59.40 | 58.42 |
| WSL CUDA/CPU NV12 | 599 | 597 | 59.70 | 59.36 |

四组传输队列丢弃均为 0，队列字节峰值 ≤ 85209。599 是连续流 parser 保留末尾未确认访问单元的结果，无协议 EOS 时不会强制提前输出。硬解 CPU 路径每组回读约 1.877 GB；**Windows CUDA CPU 中转未达持续 1080p60**。提交不等于屏幕实际显示；此结果不能代替 M6 的 30 分钟与 50 次 GPU 生命周期验收。

## D1 包与使用

已验证本地包：Windows `dist/D1-windows-v3`，WSL `/home/lqx/code/rm_udp_streamer/dist/D1-linux-v2`。两者 manifest 的实现提交均为 `2b722b4`。运行包内 `RmVideoReceiver.exe` / `RmVideoReceiver.x86_64`，设置监听地址与端口后开始接收。

两平台在空工作目录运行，PATH 移除 SDK、DOTNET_ROOT 指向不存在目录、禁用 .NET 多级查找。实际主场景/C# UI 和原生扩展均来自包；运行库跟踪确认 .NET 8.0.34 从包内加载。正式输入 640×360/60 fps，Windows 自动选择 NVIDIA D3D11VA（662 解码/653 提交），WSL 自动选择 CUDA（674/667），截图显示色条和灰阶；定时正常退出后端口可重新绑定。该验证不是全新 OS 虚拟机，操作系统仍需 GPU 驱动、图形与 .NET 原生系统依赖。原生 Ubuntu GPU 仍待实机验收。

部署/诊断参数通过 `--` 传递，例如：

```text
RmVideoReceiver.exe -- --start --bind 127.0.0.1 --port 3334 --decoder software --duration 60 --metrics run.ndjson --snapshot final.png
```

指标每秒写入、结束时补最后一项；文件必须不存在。duration 从界面启动计时，0 表示持续运行；snapshot 仅与有限 duration 使用。正常交互启动不需要参数。`-- --help` 输出完整用法。截图会产生一次整窗回读，用于诊断，独立于视频路径的像素回读计数。

`build/export_project.py` 校验锁定模板 SHA512，要求干净的已提交源码，在隔离暂存目录构建导出，检查引擎日志和实际程序集/独立运行库后才输出 manifest。发现并修复 Godot 缺少 C# solution 时仍返回 0 的假成功，以及第二次导出时 MSBuild 递归扫描暂存源码的问题。失败旧包 `dist/D1-windows` 有 INVALID 标记，不能使用。

D1 是本地阶段验证包，包含依赖锁与初步许可证说明；完整第三方许可、静态 FFmpeg 对应源码和可重链接材料在 M6 随最终 D3 完成，不应将 D1 当最终发布包向外分发。

证据摘要：[validation.json](evidence/m3/validation.json)。原始脚本、样本、日志、截图和运行库跟踪在外层 `processing/2026-11-15-m3-recovery/`；测试材料没有进入正式工程资源或导出包。
